# R2-B: Memory Efficiency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut resident memory across terminals, webviews, and markdown images without losing any user-visible history (disk absorbs it).

**Architecture:** Cap-and-eviction changes to existing caches plus one broker behavior change (observer-count-driven spool cache) and one process-wide safety net (memory-pressure purges). Spec §2 (rev 3). Depends on R2-A's broker foundation only for the history handoff task.

**Tech Stack:** Swift/AppKit, node broker, XCTest + `tests/node/`, resource gates via `npm run native:resource` (`scripts/native-resource-gate.cjs`).

## Global Constraints

- No user-visible history loss: every trim pairs with disk-backed recovery (R2-A history continuity).
- Enforced acceptance is per-window; the three-window <150 MiB figure is a tracked measurement, not a gate.
- Parked-view trims apply only when the view is pinned to the live bottom.
- Webviews share a `WKProcessPool` ONLY — configurations and data stores stay per-surface.

### Task 6: Markdown image memory

Modify `MarkdownLiveEditor.swift` (~279): placements outside a viewport window (±2 screens) drop their strong image and re-resolve on approach (layout manager already redraws on scroll). Tests: cost math; bucket keying (1x narrow miss ≠ 2x wide hit). Commit `perf(md): images cost what they weigh and stay near the viewport`.

### Task 7: Memory-pressure safety net

Wire in `KaisolaMacAppDelegate.applicationDidFinishLaunching`. Test: registry fires all purges on simulated event. Commit `perf(app): memory pressure purges every discretionary cache`.
