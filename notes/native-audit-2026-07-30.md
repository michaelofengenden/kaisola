# Kaisola Native (macOS) — Functional / Design / UI Audit

**Date:** 2026-07-30 · **Target:** `native/KaisolaMac/Kaisola` at working tree (post-1.0.0, incl. uncommitted NativePreviewSettings/NativeTerminalSurface edits)
**Method:** 7 area-focused Claude auditors (shell/nav, terminal, workspace previews, ACP+Git+Mesh, settings+copy, design system+a11y, app-core robustness) + 1 independent Codex (GPT-5.6) design critique + live-app inspection of a dev-profile launch (accessibility-tree dump + full menu-bar map; window screenshots blocked by macOS Screen Recording TCC). ~49k lines of Swift audited; every finding cites file:line, verified in code by its auditor. Detailed per-area reports follow the synthesis.

---

## Verdict

The engineering underneath is unusually strong — byte-cursor terminal replay, adversarial reconnect tests, atomic stores, a principled Liquid Glass / material system, a real security posture in the HTML preview. The weaknesses cluster in three places: (1) a handful of **silent-failure seams** where correct machinery fails without telling the user (input that stops reaching the PTY, persistence `try?`s, stale Settings targets); (2) the **last mile of the human loop** — chat text is unrendered, permission prompts aren't decision-grade, Git/preview surfaces go stale while agents work; and (3) a **design system that exists but is only ~30% adopted**, with the accessibility floor (labels, contrast, motion) the weakest layer, confirmed empirically in the running app's AX tree.

Cross-model consensus (found independently by both Claude auditors and Codex): stale Git panel, frozen-project Settings window, plain-text chat rendering, destructive "Close Chat", Mesh scroll-yank and missing run-control, marketing-style onboarding, dead-end file-preview states.

## Priority roadmap

### P0 — typing must never silently die (correctness of the core input path)
1. **Ownership-flip keeps read-only view class** — surface identity isn't keyed on `isOwned` and `TerminalSurfaceCache` returns parked views without class checks; after broker reconnect a "Live" card can permanently swallow keystrokes (`RootShellView.swift:1495-1522`, `NativeTerminalSurface.swift:1405`). The retired grid path had the guard; the live path lost it.
2. **Controller-lane death is invisible** — no disconnect handler on the write lane; `sendInput`'s `try?` swallows `notConnected` forever while the observer keeps streaming (`BrokerControlClient.swift:54`, `AppModel.swift:3719-3734`).
3. **Option-as-Meta hardcoded on** breaks international layouts (⌥-chords for `@ [ ] { } | \ ~`, dead-key accents) (`NativeTerminalSurface.swift:133`). Default off or add a setting.
4. **Blocking socket reads on the cooperative pool with no `shutdown()` on close** — every wake/reconnect can strand a thread; repeated cycles starve all Swift concurrency app-wide (`UnixBrokerTransport.swift:58-77`).

### P1 — data-loss and wrong-target hazards
5. Draft destroyed on disconnected send (chat + Mesh clear the draft before the connectivity guard drops the message) — `AcpChatView.swift:476`, `MeshView.swift:158`.
6. Duplicate transcript row IDs per turn corrupt SwiftUI diffing and are persisted — `AcpConversation.swift:722-735`.
7. Attention-jump can blank the workspace (stale target → `select(nil)`), and every window handles the jump notification — `AppModel.swift:2707`, `RootShellView.swift:66`.
8. ⌘, Settings window freezes the project captured at creation — MCP servers/account overrides silently write to the wrong project — `KaisolaMacAppDelegate.swift:2738-2748` (Codex-confirmed).
9. "Close Chat" is deletion (transcript + draft) with no confirmation or undo — `AppModel.swift:2515` (Codex). Adopt an explicit lifecycle: Hide / Stop / Close-to-Recently-Closed / Delete.
10. Mesh: no per-column or global stop; closing an active run without git changes erases work unprompted; scout send before connect wedges the pipeline for 10 min — `MeshView.swift:139`, `MeshSession.swift:846-873`.
11. Silent add-form failures in Settings: MCP 24-server cap truncates on save, duplicate-name error is dead code, account add no-ops — `McpSettingsTab.swift:372-405`, `ProjectAccountsSection.swift:167-175`.
12. Plan-usage staleness caption never renders (ms vs s epoch mismatch) — `SubscriptionCardView.swift:176`; one-line fix + test.
13. Open file previews never watch the filesystem — agents edit files while a clean preview shows stale content indefinitely — `FilePreviewView.swift` (watcher only feeds the rail). Highest-payoff fix for an agent-first product.

### P2 — the "review-and-control" 1.1 (strategic, both models converge here)
Kaisola 1.0 is built around creating/preserving execution sessions; the human loop of understanding, governing, and integrating what agents did is the gap.
- **One first-class transcript renderer** (chat + Mesh): block markdown, highlighted code with copy, clickable file:line refs, tool artifacts with truncate-and-expand; geometry-based follow with a "jump to latest" pill; unique row IDs; Mesh columns get min-width/scroll/focus modes.
- **Permission inspector**: FIFO queue (single slot today drops overlapping asks — `AcpConversation.swift:448`), full command/paths shown, Deny / Allow Once / Create Rule… with the rule's exact scope spelled out, keyboard shortcuts + VoiceOver labels.
- **Git as a project capability**: promote out of terminal context-menu into an always-available, WorkspaceWatcher-refreshed panel; split "Push & Create PR" into a composer showing base/branch/commits/title/body before anything ships.
- **Session lifecycle in-pane**: exited banner with Reopen, reconnect chip, BEL → AttentionCenter (bell is currently a silent no-op — `NativeTerminalSurface.swift:1126`).
- **Preview freshness + read-mode TextKit**: watcher-driven reload/banner; TextKit-2 read-only view fixes large-file jank, adds ⌘F in read mode, preserves scroll position.

### P3 — design system, a11y, copy (cheap, high-visibility)
- **Finish token adoption, not token design**: 54 hardcoded corner radii across 12 values vs 8 token uses; 61 ad-hoc font sizes (13 values); 14+ inline animation durations while the 3 motion tokens go unused; two different Mesh purples on one screen. Start with AcpChatView and GitPanelView (zero tokens today).
- **Accessibility floor** (confirmed live in the AX tree: dozens of `AXButton "button"` with no label, a 27-item `AXUnknown` list, `circle.hexagongrid.fill` leaking as a title): shared StatusDot with label + shape difference; contrast-safe diff colors (raw `.green`/`.red` text ≈2:1 in light mode, while TerminalTheme documents 4.5:1 hues); announce toasts; Reduce Motion support (zero checks today vs exemplary Reduce Transparency handling); palette rows as real buttons; focus-ring ↔ first-responder sync + keyboard pane cycling.
- **Copy pass, three rules**: no "broker/app-server/control lane" outside logs; Title Case buttons per HIG; "project" never "workspace". One name for the Files rail (currently "Workspace Rail" / "Files" / "file browser" with a wrong-side glyph).
- **Menu bar as source of truth**: ⌘K/⌘B/⌘L/⇧⌘O exist only as invisible buttons; palette hint teaches the wrong ⇧⌘T; ⌘W dead when no file tab; ⌘K conflicts with terminal-clear muscle memory (no Clear Terminal command exists).
- **Onboarding → readiness checklist** (broker health, adapters, account, first session) instead of feature marketing; Help currently opens a developer migration roadmap.
- **Deletions/splits**: ~350 lines of dead divergent terminal-grid UI in RootShellView (two auditors independently flagged; the dead copy contains the ownership guard the live path needs); FilePreviewView (5,523 lines) splits cleanly into ~6 units and its shared `saveError` channel already mis-styles recovery notices as errors.

## What's genuinely good (keep)
Scroll-pin engine better-engineered than most shipping terminals; replay/reattach fidelity; crash-recovery journal with two-phase fsync; exact-range markdown block editing structurally preventing the historical image-deletion bug; HTML preview JS-off/ephemeral/confined; atomic validated stores with real secret hygiene; PaneResizeHandle keyboard accessibility (best-in-class); Liquid Glass with principled Reduce-Transparency/Increased-Contrast fallbacks; quit path that persists user truth before bounded shutdown; `native:fast` 8-second edit-build-run loop.

## FINDINGS

**[high] [functional] Broker/BrokerControlClient.swift:54,386-391 + App/AppModel.swift:3719-3734** — The controller (write) lane has no disconnect handler: `BrokerControlServing` exposes none, and `abortConnection` only fails pending continuations; AppModel re-establishes control exclusively inside `restoreOwnedSessions` during an *observer* connect (AppModel.swift:4104-4135). — If only the controller socket dies while the observer stays up, `controlAvailable` stays `true` and every keystroke goes through `sendInput`'s fire-and-forget `Task { try? await controlClient.write(...) }` (AppModel.swift:3728), which swallows `notConnected` forever: the user sees a live, streaming terminal that silently ignores all typing until the next wake/reload. — Fix: add `setDisconnectHandler` to `BrokerControlServing`; on controller loss flip `controlAvailable = false` and re-run the attach flow (or funnel into `connectionLost`). No test covers controller-lane death (AppModelReconnectTests exercises only the observer client).

**[high] [lifecycle] Broker/UnixBrokerTransport.swift:58-77** — `receive` runs a blocking `Darwin.read` on the cooperative pool (`Task.detached`), and `close()` merely closes the FileHandle without `shutdown(2)`, which does not wake a kernel-blocked reader on macOS. — Every deliberate disconnect against a *quiet* terminal (sleep/wake → `recoverAfterWake` → `reload`, AppModel.swift:3008-3011; every reconnect attempt, AppModel.swift:4318) can strand one cooperative-pool thread until the broker happens to write bytes; repeated wake cycles can exhaust the pool (width = core count; two clients per window multiplies this) and stall all Swift-concurrency work app-wide — UI alive, every async path frozen. `send` (line 49-56) is likewise a blocking write on the actor when the socket buffer fills. — Fix: `shutdown(fd, SHUT_RDWR)` before close, and move socket I/O off the cooperative pool (DispatchIO/DispatchSource or a dedicated thread).

**[med] [functional] App/AppModel.swift:3991-4008** — A wedged-but-open broker is never surfaced: `refreshInventory` swallows every failure (`try? await client.inventory()`, line 3994) and only a socket-level read error reaches `connectionLost` (line 4844). — A hung broker (SIGSTOP, deadlock, full pipe) leaves the header saying "Connected" forever while inventory silently times out every 2.5 s and terminals freeze; no automatic recovery, no message. — Fix: count consecutive `requestTimedOut` inventory failures and after N force `connectionState = .unavailable` + reconnect.

**[med] [state] App/AppModel.swift:4205-4235,4247** — The disconnect handler is installed only after `connect` + `inventory` succeed (deliberately disarmed during the probe); a socket death in the suspension window between inventory success and handler install fires `abortConnection` with a nil handler, after which `connectionState` is still set to `.connected`. — Combined with the previous finding (inventory errors swallowed), the app can sit "Connected" on a dead socket with no reconnect scheduled until wake or manual reload. — Fix: after installing the handler, do one cheap liveness request (or install the handler before inventory and gate it on generation).

**[med] [lifecycle] App/AppModel.swift:4058-4083** — `refreshBranches` spawns `git rev-parse` with `waitUntilExit` and **no watchdog** (unlike `TerminalMetaService.run`'s bounded runner, Features/Sessions/TerminalMetaService.swift:154-175), sequentially over every owned cwd, and schedules a *new* detached task every 10 s with no reentrancy guard (`lastBranchScan` is stamped before the work runs). — One cwd on a dead network mount (this repo's own history: iCloud/FileProvider wedges) hangs `git` forever and accumulates one blocked cooperative-pool thread per tick until app-wide concurrency starvation. — Fix: reuse the TerminalMetaService bounded runner and skip the tick while a scan is in flight. (Same `waitUntilExit`-before-pipe-read pattern in Broker/BrokerBootstrapClient.swift:125-127 can deadlock if the bootstrap ever prints >64 KB.)

**[med] [state] App/AppModel.swift:2148-2155,1777-1790** — `restoreWorkspaceStateIfNeeded` latches `restoredWorkspaceState = true` and then `try?`-swallows `restorationState()`; `NativeWorkspaceStateStore` deliberately throws `corruptArchive`/`unsupportedSchema` (Broker/NativeSessionStore.swift:1131-1143) precisely to protect Mesh manifests — but AppModel converts that protection into a *silent* empty workspace, and every later save also fails silently (`try?` in `scheduleWorkspaceStateSave`). — After archive corruption or a downgrade, the user loses all restored chats/panes/meshes with zero explanation and no retry for the app's lifetime. — Fix: surface a toast/banner distinguishing "corrupt archive" from "empty", and keep a rename-aside recovery path.

**[med] [perf] Broker/ObserveOnlyBrokerClient.swift:44-45,241-290 + App/AppModel.swift:85,3294-3307** — Every cold subscribe eagerly pages spool history up to 64 MiB (`historyRetainedBytes`, up to 16 sequential 4 MiB requests at 5 s timeout each), and AppModel's LRU retains up to 12 such documents plus their SwiftTerm buffers. — Worst-case ~768 MiB of retained scrollback strings after touring a dozen long-lived agent terminals, and multi-second cold-select latency on large spools. — Fix: subscribe with a small tail (4–8 MiB) and page older history on demand (the transcript viewer already does exactly this).

**[med] [functional] App/AppModel.swift:3719-3734** — Beyond the dead-lane case: `sendInput` swallows *all* write failures (stale-owner rejection, exited terminal) and spawns one unstructured Task per keystroke, so cross-keystroke wire ordering rests on undocumented FIFO actor scheduling (each `request` additionally spawns its own inner send Task, BrokerControlClient.swift:299-303). — Dropped or (theoretically) reordered input with no user feedback. — Fix: per-terminal serialized write queue (AsyncStream consumer) + surface repeated failures via ToastCenter.

**[med] [functional] Broker/NativeSessionStore.swift:479-503** — `write` updates the in-process cache first, then silently discards any disk failure (`catch { try? removeItem }` with no signal). — The running app stays coherent, but on relaunch the owned-session registry / project tabs silently revert, orphaning broker PTYs this install created (recovery depends on the broker's `wasOwned` capability *and* a persisted open project, NativeSessionStore.swift:225-251). — Fix: surface persistent write failure once (disk full is the realistic trigger) instead of never.

**[low] [functional] App/KaisolaMacAppDelegate.swift:1853-1857** — `keyModel()` falls back to `windowModels.values.first` (unordered dictionary). — With no key window, menu commands and the Settings sign-in "run in terminal" notification (line 831-839) target an arbitrary window/project; the spawned shell can land in the wrong workspace. — Fix: track last-key-window explicitly.

**[low] [lifecycle] App/KaisolaMacAppDelegate.swift:2517-2526** — `windowWillClose` stores a teardown Task in `teardownTasks` that is only ever removed by the termination drain (2481-2491). — Long sessions that open/close many windows accumulate completed Task objects (and force the quit path through the drain loop even when idle); similarly AppModel's `chatShutdownTasks` (deliberate), `splitIntentTokens`, and `explicitlyClosedChatIDs` (AppModel.swift:242,325) grow monotonically. — Fix: remove entries on task completion.

**[low] [functional] App/KaisolaMacAppDelegate.swift:2584-2596** — `popOut(sessionID:)` polls 5 s for connection and then selects unconditionally; if the broker connects late or the session is gone, the new window silently shows nothing. — Fix: after the wait, show the standard failure card when the session is absent.

**[low] [state] Broker/ObserveOnlyBrokerClient.swift:77-110** — A second `connect` while `helloWaiter` is pending overwrites the continuation, leaking the first caller forever; and `if let hello { return hello }` means dialing a *different* broker requires a prior explicit `disconnect`. — Currently unreachable through AppModel's generation-serialized flow (including the fallback path, which disconnects first at AppModel.swift:4224), but nothing in the client enforces it. — Fix: throw `.alreadyConnecting` instead of replacing the waiter.

**[low] [perf] App/AppModel.swift:4021-4045** — `refreshMeta` spawns `ps` + one `lsof` per owned PID chain every 5 s even when fully idle (bounded by the watchdog, so safe, but constant background process churn on machines with many owned sessions). — Fix: batch into a single `lsof -p pid1,pid2,...` invocation and skip when no UI surfaces meta.

## TOP IMPROVEMENTS

1. **Controller-lane health contract**: disconnect notification on `BrokerControlServing`, automatic re-attach, and non-silent input failures — this is the one defect class where the user actively loses typed input with zero feedback.
2. **Transport hardening**: `shutdown()`-before-close and socket I/O off the cooperative pool in `UnixBrokerTransport` — removes an entire class of slow-burn thread-starvation hangs triggered by ordinary sleep/wake cycles.
3. **Liveness policy above the socket**: N-consecutive-timeout ⇒ reconnect for the inventory heartbeat, closing both the wedged-broker and the disarmed-handler-window gaps with one mechanism (and a test in AppModelReconnectTests).
4. **A "consequential `try?`" pass**: workspace-archive corruption, session-store write failure, and draft/transcript persistence all fail invisibly today; route them through one surfaced-error chokepoint (ToastCenter + a degraded-state flag) so data-affecting failures are never silent.
5. **Bounded process-spawn helper**: make `TerminalMetaService.run` the mandatory runner for every `Process` in the app (git branches, bootstrap) with timeout + reentrancy gating.

## OVERALL ASSESSMENT

The core state machine is unusually disciplined for its size: generation counters, intent tokens, and the 16 ms output coalescer are all verified by genuinely adversarial reconnect/race tests (AppModelReconnectTests covers blocked-subscribe/minimize/promote interleavings most codebases never test), and the quit path persists user truth *before* asking anything to shut down under a 12 s bounded drain. The real weaknesses sit below the model, not in it: the transport blocks cooperative threads and can't be woken, the write lane has no health signal, and a family of `try?`s converts consequential persistence and liveness failures into silent degradation the user discovers only as "it stopped working". AppModel's monolith risk is mostly organizational rather than currently buggy — its one concrete architectural debt is that connection health is inferred solely from the observer socket while three other lanes (controller, inventory requests, persistence stores) can each fail independently and invisibly.

**TOP IMPROVEMENTS**

1. **Make the input path ownership-proof** — key surface identity on ownedness, validate cached view class on claim, and add a regression test that flips `ownedTerminalIDs` across a mounted card and asserts bytes still reach `onInput`. This closes the only defect found that can silently kill typing.
2. **In-pane session lifecycle layer** — exited banner with one-click Reopen, disconnect/reconnecting chip, and bell → AttentionCenter badge + optional sound. This is the largest gap vs Terminal.app/iTerm and the highest-value one for an agent-orchestration product where "the agent wants you" is the core event.
3. **International keyboard correctness** — default Option-as-Meta off (or per-layout auto), expose it in Settings → Terminal beside font/palette, and document ⌥⌘O. Without this the terminal is broken for a large fraction of non-US users.
4. **Follow-mode affordances** — a "new output ↓" jump-to-bottom pill while unpinned, ⌥⌘K clear, and pane-focus keyboard cycling synced with the focus ring. The pin engine itself is excellent (and now well-tested); it just lacks the visible handles users expect.

**OVERALL ASSESSMENT**

## H. Codex (GPT-5.6) independent critique

Scope: this is an independent, source-based design/UX audit of the current native macOS checkout, intended for synthesis with the separate Claude audit. No code edits were wanted or made.

## Top 10 critiques, ranked by impact

1. **Permission prompts are not decision-grade.** The request model contains the action kind and affected paths, but the UI reduces that information to a title, a generic "Sensitive file" label, and "Always allow matching requests." ## Five highest-leverage improvements

1. **Workspace-level Review Workbench** — persistent Run/Review mode per project combining file tree, selected file/diff, live Git status, commits, and agent artifacts; tool-call paths open directly into it; replace the modal Git panel with a continuously refreshed inspector; PR creation becomes a second-stage composer showing base, branch, commits, files, title/body before pushing.

2. **Permission Inspector replacing permission strips** — exact action type, command/resource, workspace, full affected paths, expandable raw request; three explicit choices `Deny` / `Allow Once` / `Create Rule…`, the last opening a confirmation sheet spelling out the exact persistent rule scope.

3. **Reversible lifecycle model** — distinguish `Hide` / `Stop Current Turn` / `Stop All` / `Close` / `Delete`. Mesh gets per-column stop plus global stop. Closing an active run confirms; closing inactive chat/Mesh moves to "Recently Closed" with transcripts/drafts preserved and an Undo toast. Permanent deletion is separate and explicit.

4. **One first-class transcript renderer for Chat and Mesh** — block Markdown, syntax-highlighted code with copy buttons, tables, clickable file/line references, inline diffs, expandable tool artifacts; streaming follows bottom only if user was already pinned there; Mesh gets minimum-width columns, horizontal scroll, two-up comparison, single-agent focus.

5. **Onboarding as operational readiness checklist** — detect broker/control health, installed adapters, authenticated accounts, update readiness; guide to choosing a project and launching one terminal/chat, with an action beside each failed check; Help provides a real user manual/shortcuts/troubleshooting, not internal migration docs.

## Strategic design weakness

Kaisola 1.0 is designed around creating and preserving execution sessions, not around helping a human understand, govern, and integrate what those sessions do. Durable terminals and multiple agent surfaces are impressive infrastructure, but the critical human loop is fragmented across raw chat text, collapsed tool cards, underspecified permission prompts, a cramped file preview, and a terminal-attached modal Git panel. A design-led 1.1 should be a **review-and-control release**: unify artifacts and repository state into one workbench, make every consequential action legible and previewable, and make session lifecycle reversible. Adding more agents, settings, or orchestration modes before fixing that loop would deepen the product's central weakness.
